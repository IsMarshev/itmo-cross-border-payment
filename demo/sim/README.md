# Симуляция

Календарь идёт вперёд по одному дню. Слева телефон клиента, справа график
коридора. Когда слой находит день, симуляция сама встаёт на паузу и на экран
блокировки прилетает пуш — дальше решает человек за стендом.

```bash
docker compose up --build            # → http://localhost:8100
uv run python demo/sim/server.py     # то же самое без докера
```

Первый сигнал приходит на четвёртом шаге. Контейнер отдаёт и статический стенд
кейса — на `/stand/`.

Слой считает хронологический walk-forward один раз при старте (~3 с на пять
коридоров), поэтому контейнер поднимается уже готовым: `healthcheck` зеленеет,
когда `/api/corridors` начинает отвечать.

## Как этим играть

**«Симуляция»** запускает отсчёт дней, **«Пауза»** останавливает. Сигнал ставит
паузу сам.

Дальше есть развилка, ради которой стенд и сделан:

- открыть пуш сразу — факт ещё верен, форма перевода предзаполнена;
- **не открывать**, нажать «Симуляция» ещё раз и остановиться через два-три
  дня — курс за это время ушёл, и на открытии клиент увидит другое: плашку со
  снимком данных, если сдвиг мелкий, и модальное окно «данные были актуальны
  на дд.мм.гггг», если сдвиг больше обычного дневного движения коридора.

Пуш остаётся на экране блокировки и стареет вместе с календарём — его можно
открыть, вернуться назад, прогнать ещё несколько дней и открыть снова, чтобы
увидеть, как меняется ответ. Кнопка «Перевести» закрывает уведомление: клиент
принял решение.

Переключение коридора начинает прогон заново — у каждого коридора свой темп и
свой порог. Когда данные заканчиваются, «Симуляция» запускает всё сначала.

## Что считает backend

Фронт не знает ни одного правила: он двигает дату и спрашивает.

| Запрос | Ответ |
|---|---|
| `GET /api/corridors` | коридоры, старт симуляции, порог раскрытия, окно тренда |
| `GET /api/series/{iso}` | ряд курсов и EWMA — график открывает его по мере хода дней |
| `GET /api/day/{iso}?on=` | решение слоя на этот календарный день: `candidate` с текстом пуша или `hold` |
| `GET /api/freshness/{iso}?signal_date=&as_of=` | `same` / `better` / `mild` / `stale` и сдвиг в базисных пунктах |

Логика живёт в [`signal_layer.services.simulation`](../../src/signal_layer/services/simulation.py),
поверх той же точки входа `signal_layer.signals`, которую выбрал бенчмарк.
Хронологический прогон считается один раз при старте (~3 с) — это тот же
walk-forward, что и `signals_asof` на каждый день, поэтому шаг дня стоит
миллисекунды, а не полсекунды.

Порог между плашкой и модальным окном — медианное дневное движение самого
коридора (TJS 53 б.п., UZS 60, KGS 52, AMD 53, KZT 62). Раскрытие асимметрично:
подтверждение просим, только когда курс ушёл против клиента.
