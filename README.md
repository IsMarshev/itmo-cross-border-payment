# Валютные сигналы для трансграничных переводов

Воспроизводимый исследовательский пайплайн для RUB→TJS/UZS/KGS/AMD/KZT:
данные ЦБ → признаки → несколько оценок исхода → калибровка → решение
«отправить / ждать / пропустить» → walk-forward-бэктест → автономный HTML-дашборд.

Реализация находится в ветке `test_feature`. CSV перенесены **без изменения содержимого**
из `m0/currency_data`, коммит `c01eb1ef2e554a4368c6bc7d2168164f27094646`.
Ранняя реализация `m0` не используется как проверенная база метрик.

## Быстрый запуск

Нужны Python 3.11–3.13 и [uv](https://docs.astral.sh/uv/getting-started/installation/).
Все команды выполняются из корня репозитория. `uv.lock` фиксирует зависимости.

```bash
git switch test_feature
uv sync --locked

# Короткая проверка на настоящих данных: все методы, два будущих периода, HTML.
uv run fx-signals backtest --config configs/smoke.yaml --out reports/smoke

# Полный пайплайн одной командой: бэктест, сравнения, дашборд и финальные модели.
uv run fx-signals run --config configs/default.yaml --out reports/full
```

Результаты полного запуска:

- `reports/full/dashboard.html` — открыть обычным браузером, сервер и интернет не нужны;
- `reports/full/final_model/model.joblib` — комплект обученных моделей, калибраторов и правил;
- `reports/full/folds/` — отдельные модели и решения каждого исторического периода;
- `reports/full/summary.csv` — сравнение методов, коридоров, сценариев и горизонтов;
- `reports/full/signals.csv` — только отправленные сигналы;
- `reports/full/decisions.csv.gz` — все решения, включая ожидания и отказы.

Короткий запуск проверяет работоспособность, **не доказывает качество модели**.
Нулевой поток, недостаток данных для калибровки и недостижение lift явно отражаются
в отчёте. Частота не увеличивается принудительными слабыми пушами.

## Отдельные операции

```bash
# Только обучение всех выбранных методов и калибровка политики.
uv run fx-signals train --config configs/default.yaml --out artifacts/model

# Обучение на историческую дату; более поздние данные не используются.
uv run fx-signals train --config configs/default.yaml --as-of 2025-12-31 --out artifacts/2025-12-31

# Только walk-forward; каждый фолд сам обучает свои модели на прошлом.
uv run fx-signals backtest --config configs/default.yaml --out reports/backtest

# Продолжение прерванного идентичного запуска: готовые модели фолдов переиспользуются.
uv run fx-signals backtest --config configs/default.yaml --out reports/backtest --resume

# Повторно собрать HTML из CSV, без обучения и повторного бэктеста.
uv run fx-signals dashboard --run reports/backtest

# Посмотреть подготовленные признаки и разметку.
uv run fx-signals prepare --config configs/default.yaml --out artifacts/prepared

# Выбрать подмножество методов/коридоров без изменения YAML.
uv run fx-signals train --config configs/default.yaml --methods catboost linear --corridors TJS KZT --out artifacts/two-corridors

# Обновить публичные данные отдельно. Обучение и бэктест работают полностью офлайн.
uv run fx-signals fetch --start 2011-01-01 --end 2026-09-02 --out currency_data
```

Каталоги с существующими результатами не перезаписываются случайно. Для продолжения
бэктеста используйте `--resume`; при изменении кода, зависимостей, данных или конфигурации
создайте новый каталог. Возобновление экономит обучение; решения и метрики пересчитываются.

## Единая точка использования

CLI:

```bash
# Точное историческое решение с правильной моделью, бюджетом и состоянием эпизодов.
uv run fx-signals signals --artifact reports/backtest --as-of 2025-05-15 --method catboost --corridor TJS

# Использование отдельного артефакта после даты его обучения.
uv run fx-signals signals --artifact artifacts/2025-12-31 --as-of 2026-01-15 --method catboost

# Новые CSV вместо сохранённого снимка данных, результат в JSON.
uv run fx-signals signals --artifact artifacts/model --data-dir currency_data --as-of 2026-09-02 --out artifacts/signals.json
```

Python API:

```python
from signal_layer import SignalEngine

engine = SignalEngine("configs/default.yaml")
engine.train("artifacts/model")
engine.backtest("reports/backtest")

archive = SignalEngine.load("reports/backtest")
signals = archive.signals("2025-05-15", method="catboost", corridor="TJS")
SignalEngine.dashboard("reports/backtest")
```

`signals()` возвращает таблицу решений, а не инициирует отправку сообщений. В ней есть
`date`, `iso`, `indicator`, `direction`, `strength`, `speed`, `scenario`, `decision`,
`reason`, вероятности исходов, границы риска, `episode_id`, выбранные пороги и текст
пуша для отправленного сигнала. В день без новой котировки возвращается отказ
`no_new_observation`. Артефакт из будущего нельзя применить к прошлой дате.

Архив бэктеста воспроизводит цепочку моделей и коммуникационных состояний.
Отдельный артефакт начинает новую историю решений с даты обучения. Для продолжения
реального ранее работавшего сервиса необходимо передать его состояние коммуникаций;
промышленная CRM-интеграция не входит в эту реализацию.

## Что реализовано

| Компонент | Реализация |
|---|---|
| Данные | Нормирование номиналов, проверка CSV, дата действия ЦБ, снимки и SHA-256 |
| Две шкалы времени | Реальные обновления для признаков; календарные дни для исходов |
| Признаки | Уровень, моментум, отскок, волатильность, режим, валютный контекст, календарь |
| Обучаемые исходы | Локальный минимум, отсутствие существенного дальнейшего удешевления, сохранение условий, подтверждённый рост |
| Величина ошибки | Регрессии выгоды, упущенной возможности, ухудшения условий и ценности ожидания |
| Основной ML | Пул моделей CatBoost, односторонние квантильные оценки риска |
| Калибровка | Sigmoid-калибровка на отдельном прошлом участке; отдельные карты для коридоров при достаточном числе примеров |
| Неопределённость | Односторонняя conformal-коррекция остатков и адаптация только после созревания меток |
| Быстрый/медленный сигнал | Ограниченное ожидание с повторной оценкой, истечение эпизодов, анализ всех эпизодов |
| Поток пушей | Не более двух за скользящие 7 дней, cooldown, дедупликация эпизодов, цена последнего контакта |
| Бэктест | Rolling origin, разделённые train/calibration/tuning, purge по `label_known_on`, сохранение фолдов |
| Контроли | Линейная модель, random walk, drift, AR(1), ETS, правила, случайный день и случайная политика |
| Абляции | CatBoost без ожидания, фильтра границ риска и явных признаков режима |
| Дашборд | Фильтры, курс и сигналы, lift/выгода с интервалами, периоды, частота, калибровка, ожидания, журнал и CSV-выгрузка |

## Настройка

Все параметры находятся в YAML; неизвестные ключи вызывают ошибку.
Полный набор с пояснениями — [docs/configuration.md](docs/configuration.md).

Наиболее полезные параметры: `model.iterations`, `model.threads`,
`targets.primary_horizon`, `risk.regret_penalty`, `policy.regret_cap_bps`,
`policy.probability_thresholds`, `backtest.start`, `backtest.end` и `backtest.fold_days`.

Пороги для разметки фиксируются до оценки и не оптимизируются на тесте.
Сетки параметров политики калибруются отдельно по коридорам на прошлом участке.
Праздники можно подключить CSV с `iso,date,known_on,name`; шаблон —
`configs/holidays_template.csv`. Исторические даты объявления не выдумываются.

## Проверки

```bash
uv run pytest -q
uv run ruff check src tests
uv run ruff format --check src tests
```

Тесты проверяют временные границы, мутацию будущего, направления рисков, календарные
метки, номиналы, ограничение уведомлений между фолдами, delayed feedback,
историческое воспроизведение и сквозную генерацию отчёта. ML проверяется на небольшом
числе итераций; полноценное обучение запускается пользователем.

[Результаты технической проверки и пример дашборда](docs/validation.md).
