# Методика сигнального слоя

## Контракт времени и данных

`p_t = rate / nominal`: рубли за единицу валюты получателя. Ниже — выгоднее
для перевода фиксированной рублёвой суммы. Поле `Date` XML ЦБ обозначает дату
действия курса. В этой реализации значение становится доступным с этой даты;
`availability_lag_days` может только добавить задержку. Предыдущий день публикации
не реконструируется без исторического подтверждения времени публикации.

Источник: [XML Банка России](https://cbr.ru/development/sxml/),
[срок действия](https://www.cbr.ru/Reception/TopicalMessage/Page/2656),
[время публикации](https://www.cbr.ru/Reception/TopicalMessage/Page/2661).

Каждая строка источника — обновление, даже если цена совпала с предыдущей.
Календарное перенесение не добавляет строки в признаки. Для целей строится
календарный ряд с переносом последнего известного курса, без обратного заполнения.
Пропуск длиннее `max_stale_days` делает соответствующие окна непригодными.
Хвост без наблюдаемого окончания окна не получает готовой метки.
Дополнительно требуется не менее 8 обновлений за предыдущие 30 календарных дней:
ранние месячные участки некоторых валют не выдаются за ежедневную историю.

Контекст USD/EUR/CNY присоединяется только назад по времени (`merge_asof`).
Все rolling-признаки доступны на дату строки; центрированные окна существуют
только в отдельной таблице исходов.

## Признаки и объяснение

Окна 5/20/60/120 обновлений: логизменение, процентиль относительно предыдущих
наблюдений, расстояние до медианы и волатильность. Дополнительно считаются серии
снижения, ускорение, отскок от предыдущего 20-периодного минимума, валютный контекст,
время между обновлениями, календарные циклы и опциональные известные праздники.
При равенстве цен процентиль модели учитывает половину совпадений; текстовый
процентиль считает строго более дорогие календарные дни.

Режим определяется причинными правилами: скачок, повышенная волатильность,
выраженный тренд либо диапазон. Границы режимов не подгоняются на будущем.
В состоянии скачка порог вероятности увеличивается на 0.10 (до максимума 0.99).

Модель объединяет признаки индикаторов и их взаимодействия. `feature_importance.csv`
показывает вклад признаков по каждой голове; для линейной модели это коэффициенты
на стандартизированных признаках. Эти коэффициенты не являются вероятностями
правдивости текста или доказательством причинности.

## Разметка и единицы

Все `h` — **календарные дни**. Основной горизонт по умолчанию — 5 дней;
горизонт открытия — 1 день. Все метрики также считаются для 1/3/5/10/20 дней.
Обозначим `W=[t-h,t+h]`, `F=[t+1,t+h]`; 10 000 б.п. = 100%.

| Исход | Определение |
|---|---|
| `local_min_h` | `10000 × (p_t / min(W) − 1) ≤ near_min_bps` |
| `regret_bps_h` | `10000 × (p_t / min(p_t, min(F)) − 1)` |
| `no_regret_h` | `regret_bps_h ≤ regret_tolerance_bps` |
| `stale_bps_h` | `10000 × (1 − p_t / max(p_t, max(F)))` |
| `hold_h` | `stale_bps_h ≤ hold_tolerance_bps` |
| `close_h` | `10000 × (p_(t+h) / p_t − 1) ≥ closing_bps` |
| `gain_bps_h` | `10000 × (1 − p_t / mean(W))` |

`regret` — относительная дополнительная сумма валюты, которую можно было бы
получить, дождавшись лучшего дня. `stale` — доля суммы получателя, потерянная
при ухудшении цены после уведомления. Это два разных направления риска.
`gain` — скидка цены относительно среднего в локальном окне, не P&L и не фактически
реализованный прирост валюты при переводе. Нельзя смешивать эти три показателя.

Hit для сообщения `favourable_now` — `hold_h`; для `window_closing` — `close_h`.
Близость к минимуму и отсутствие дальнейшего удешевления выводятся отдельно.
Истинность факта в пуше проверяется на дату отправки, будущие метрики оценивают
полезность момента. Правдивый исторический факт сам по себе не доказывает хороший тайминг.

## Модели

Четыре классификатора оценивают local_min, no_regret, hold и close. Четыре
регрессора — gain, regret, stale и wait_delta. Для hold/stale используется
горизонт открытия, для остальных исходов — основной горизонт.

CatBoost обучается на панели коридоров, с one-hot признаками валюты и режима,
без target encoding. Для рисков дополнительно обучаются верхние квантильные модели.
Линейный контроль использует стандартизацию, LogisticRegression и Ridge; все
преобразования обучаются только на train. Одноклассовые головы обрабатываются явно.
Не используется генеративный ИИ или скрытый сетевой сервис.

Классические контроли прогнозируют распределение траекторий с воспроизводимыми
гауссовскими инновациями: random walk, random walk с дрейфом, AR(1) на логизменениях,
экспоненциальное сглаживание логизменений (ETS(A,N,N)). Параметры движения/шума
обновляются по trailing-истории известных цен, не по будущим меткам. Расписание
обычных обновлений оценивается из прошлого; неожиданные праздничные изменения
расписания не считаются заранее известными. Это базовые модели, а не точные модели
всех особенностей рынка. Из траекторий получаются те же исходы, что у ML.

Для каждого дня/валюты используются одинаковые случайные инновации у разных
статистических методов: различия не должны создаваться независимым шумом симуляции.
Риск также проверяется на реальных out-of-time исходах.

Прозрачные контроли: уровень, моментум, отскок и исторический месячный профиль
с уменьшением малых выборок к общему среднему. Они подчиняются лимитам и эпизодам,
но не фильтруются ML-вероятностями. Сравнивается вся политика, а диагностические
метрики отдельно показывают качество самих вероятностей.

## Временное обучение

Для каждого будущего блока фиксируется `cutoff = начало блока − 1 день`.
Перед ним располагаются train, calibration и tuning, строго в этом порядке.

1. В train допускаются только метки, полностью известные **до** начала calibration.
2. На calibration обучаются отображения вероятностей и первоначальные поправки риска.
   Его метки должны созреть **до** начала tuning.
3. На tuning перебираются только заданные параметры политики, с метками,
   известными к cutoff. Здесь же симулируются cooldown, ожидание и эпизоды.
4. На test нельзя подбирать параметры, выбирать лучший горизонт или переучивать
   классификаторы до следующего заранее заданного фолда.

`label_known_on` — максимальная дата созревания всех используемых голов, включая
исход следующего обновления для wait_delta. Просто исключить последние h строк
недостаточно: h измеряется в календарных днях, а обновления нерегулярны.

Один общий календарный split применяется ко всем валютам. Коридоры не считаются
независимыми доказательствами: рублёвый компонент общий. Последние 180 дней
помечены holdout; конфигурация не выбирается по ним. Предварительно заданные
переобучения на уже известных данных продолжаются и внутри holdout — это
последовательная оценка зафиксированного алгоритма, а не один замороженный весовой файл.

## Калибровка и риск

Sigmoid-калибровка использует логиты out-of-sample вероятностей. Есть общая карта
и отдельные карты коридоров при достаточном числе примеров. Значения Brier и ECE
выводятся для всех прогнозов и отдельно для отправленных пушей.

Верхняя оценка риска корректируется квантилием прошлых остатков `факт − q_model`.
При достаточной истории используется группа «коридор × режим», иначе весь коридор.
Буфер ограничен по размеру. В адаптивной версии уровень ошибки изменяется после
получения созревшего исхода; немедленная обратная связь на горизонте 20 дней запрещена.
При смене модели буфер инициализируется её собственными калибровочными остатками,
а старые ошибки модели не переносятся в новую шкалу. Коммуникационные состояния сохраняются.

Это эмпирический контроль риска с conformal-коррекцией. Здесь **не заявляется**
безусловная или условная 90% гарантия при любой смене распределения. Покрытие на
всех прогнозах не равно точности отобранных пушей; обе выборки проверяются.
Методическая основа: [Adaptive Conformal Predictions for Time Series](https://proceedings.mlr.press/v162/zaffran22a.html),
[калибровка вероятностей](https://scikit-learn.org/stable/modules/calibration.html),
[квантильные функции CatBoost](https://catboost.ai/docs/en/concepts/loss-functions-regression).

## Решение и цена ожидания

Оценка немедленной отправки, в условных б.п. полезности:

`U = E[gain] − λ E[regret] − μ E[stale] − contact_cost`.

По умолчанию λ=3 и μ=1. Это продуктовые предпочтения, не измеренная денежная цена
раздражения клиента. При последнем оставшемся контакте применяется дополнительная
цена. Пуш требует положительного U, минимальной выгоды, достаточной вероятности
соответствующего сценария и приемлемых верхних границ риска.

Кандидат возникает при низком процентиле или серии снижения. Сигнал отскока
требует одновременно низкого относительного уровня, положительного последнего
изменения и достаточного отскока. Несколько индикаторов объединяются в один эпизод.

Для следующего обновления j рассчитывается
`C_wait = 10000 × (1 − p_t/p_j)`.
Положительное значение означает уменьшение суммы получателя за фиксированные рубли.
Модель wait_delta прогнозирует `−C_wait + λ(regret_t−regret_j) + μ(stale_t−stale_j)`.
Это оценка одного шага ожидания, а не решение полного уравнения оптимальной остановки.
На следующем наблюдении решение пересчитывается; ждать можно ограниченное число
обновлений и дней. Если подтверждение/качество не появились, эпизод истекает без
автоматического позднего пуша.

Отдельный отчёт сопоставляет первый быстрый повод с первым последующим отскоком
в пределах окна. В нём остаются эпизоды без подтверждения: для политики «дождаться
подтверждения» они означают пропуск с нулевой полезностью. Цена ожидания среди
подтвердившихся выводится отдельно от средней разницы полезности по всем эпизодам.
Последняя — диагностический контрфактический proxy, не измеренный клиентский uplift.

## Ограничения потока

Не более двух отправок в скользящем окне 7 дней, минимум 3 календарных дня между
ними, один пуш на эпизод. Эпизод переоткрывается после нескольких обновлений вне
условий кандидата или существенного нового улучшения цены. Бюджет и состояние
эпизодов не обнуляются на границе фолда. Лучшие дни недели никогда не выбираются задним числом.

Сетка level/probability/contact_cost оценивается отдельно по коридорам. Выбирается
максимальная реализованная risk-adjusted полезность на неделю среди вариантов
с достаточным числом калибровочных отправок. Если данных для выбора нет, политика
отключается с явной причиной. Порог минимальной частоты не обеспечивается
принудительно: недостижение 1–2 сигналов в неделю остаётся отрицательным результатом.

## Базы сравнения и статистика

Случайный день выбирается из тех же доступных дат, той же валюты и месяца.
Для каждого метода сохраняются количество и смесь сценариев его фактических
отправок; метрика сравнивается с математическим ожиданием случайного дня.
Дополнительно сохраняются повторные случайные выборки с фиксированными seeds.
Это не политика отправки: у такого контроля нет cooldown.

Случайная политика — отдельный последовательный Bernoulli-процесс с заранее
заданной вероятностью, тем же cooldown и недельным потолком. Множество seeds
показывает разброс результата. Её фактическое число отправок может отличаться:
подгонка к ещё неизвестному числу будущих сигналов запрещена.

95% интервалы рассчитываются блочным bootstrap по последовательным календарным
блокам, включая блоки без сигналов. Для ALL используются общие даты и общие
перевыборки всех валют. При недостатке блоков интервалы не выводятся.
Интервалы приближённые; они не корректируют перебор множества экспериментов пользователем.
Поэтому итоговую конфигурацию необходимо фиксировать до просмотра holdout.

Если базовый hit случайного дня выше 1/1.3, lift≥1.3 математически недостижим даже
при идеальном сигнале. `max_possible_lift` показывает этот предел; нельзя подбирать
допуски разметки на тесте для обхода ограничения.

Критерий promising в отчёте требует lift≥1.3, нижней границы lift>1, нижней границы
выгоды>0 и целевой средней частоты. Сильный средний результат не заменяет проверку
отдельных периодов. Шарп, торговый P&L, конверсия и реальные суммы банковского
исполнения здесь не моделируются.
