## Если сигналов нет

Сначала изучите `folds/*/policy_trials.csv` и `policy.json`, затем журнал решений.
Это разные ситуации, требующие разных действий:

| Причина | Интерпретация |
|---|---|
| `insufficient_calibration_evidence` | Ни одна заданная комбинация не набрала минимальное число tuning-сигналов |
| `no_candidate` | Нет фактического повода по выбранному правилу |
| `risk_bound` | Верхняя оценка риска превышает допустимую |
| `low_probability` | Вероятность исхода недостаточна |
| `nonpositive_value` | Ожидаемая выгода не компенсирует взвешенные риски/контакт |
| `waiting_has_value` | Оценка одного шага ожидания выше заданной границы |
| `awaiting_confirmation` | Ожидание улучшения качества кандидата |
| `wait_expired` | Подтверждение не получено в пределах окна |
| `episode_already_used` | По этому движению уже отправляли |
| `weekly_budget` / `cooldown` | Достигнут лимит коммуникаций |
| `no_new_observation` | В эту дату нет нового наблюдения источника |
| `insufficient_history` | Нет достаточного прогрева/контекста для признаков |

Увеличение числа итераций не гарантирует появление сигнала. Допускается исследовать
другие окна и цены ошибок на development-периоде, но нельзя выбирать их по holdout.
Уменьшение требований к риску — продуктовый компромисс, который должен быть виден
в новой конфигурации и новом отчёте.

## Производительность

Данные и признаки строятся один раз за запуск. Модели обучаются раз в фолд, а не
каждый день. Абляции без ожидания/границ используют уже обученные головы; версия
без режима требует отдельного обучения. Снижение `simulation_paths`,
`random_repeats`, числа методов и коридоров ускоряет исследовательские прогоны.
`configs/smoke.yaml` предназначен именно для проверки интерфейсов и артефактов.

`run` обучает дополнительно финальный артефакт на последнюю общую доступную дату.
Он не используется для пересчёта прошлых тестовых метрик. Для экономии времени
запускайте `backtest` и `train` раздельно.
