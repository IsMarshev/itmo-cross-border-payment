# Контракт результатов

| Файл | Содержание |
|---|---|
| `config.yaml` | Конфигурация запуска |
| `manifest.json` | Статус, даты, конфигурация, версии пакетов, SHA-256 данных и кода, список фолдов |
| `data/` | Копия использованных исходных CSV для переносимого воспроизведения |
| `folds/<id>/model.joblib` | Модели, калибраторы, начальные остатки риска и параметры политик фолда |
| `folds/<id>/metadata.json` | Границы train/calibration/tuning, число строк, последняя дата созревания меток |
| `folds/<id>/policy.json` | Выбранные параметры по методам/коридорам и причины отключения |
| `folds/<id>/policy_trials.csv` | Все испытанные комбинации порогов на tuning; не тестовые метрики |
| `folds/<id>/feature_importance.csv` | Вклад признаков/линейные коэффициенты по головам |
| `decisions.csv.gz` | Все решения на каждом допустимом обновлении |
| `signals.csv` | Подмножество с decision=send |
| `outcomes.csv.gz` | Будущие исходы, горизонты и `label_known_on`; отдельно от входов модели |
| `summary.csv` | Метод × коридор/ALL × сценарий × горизонт, интервалы и частота |
| `fold_metrics.csv` | Та же матрица по будущим периодам и development/holdout |
| `diagnostics.csv` | Brier, ECE, покрытие границ и ошибка величины риска |
| `calibration.csv` | Бины графика надёжности для всех прогнозов и выбранных пушей |
| `waiting_episodes.csv` | Все быстрые эпизоды, подтверждения/их отсутствие и цена ожидания |
| `random_day_draws.csv` | Случайные дни с числом событий и смесью сценариев соответствующего метода |
| `random_policy_draws.csv` | Независимые последовательные случайные политики с такими же жёсткими лимитами |
| `dashboard.html` | Автономный отчёт с включёнными данными и Plotly |
| `final_model/` | Дополнительный актуальный комплект моделей после команды `run` |

`ALL` агрегирует события коридоров. Частота и пустые недели нормируются по числу
коридоров; bootstrap использует совместные календарные блоки. Данные с нулевым
числом событий не превращаются в hit=100% или gain=0: неопределимые метрики — NaN.

`valid_until` — срок пересмотра аналитического сигнала по горизонту открытия,
**не фиксация банковского курса**. После появления нового наблюдения требуется
новый вызов движка. В production перед отправкой и при открытии проверяется
актуальная котировка приложения.

Исторический архив загружается через `SignalEngine.load(<run_directory>)`.
Движок выбирает сохранённую модель каждого фолда и заново последовательно
воспроизводит решения, включая бюджет и эпизоды. Подмена прошлой модели более
поздней запрещена. Несовпадение исходного кода с артефактом вызывает отказ: для
точного воспроизведения нужен первоначальный revision либо новый бэктест.

Сохранённые модели — формат joblib/pickle: загружайте собственные проверенные
артефакты. Нельзя принимать произвольный файл модели от внешнего пользователя
через публичный API. `signals()` не является HTTP-сервисом и не отправляет пуши.

Сами большие результаты, веса и окружения исключены из git. Для совместного
использования можно передавать весь каталог запуска: данные сохранены рядом,
внутренние пути моделей относительно корня отчёта.
