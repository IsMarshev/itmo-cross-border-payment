# Handoff: сигнальный слой трансграничных переводов

Состояние на 2026-09-03, ветка `m0`. Этот файл — чтобы коллега, который
перехватит задачу, за 10 минут понял, где мы, что сделали, что нашли и что

---

## 1. Коротко: где мы

Строим сигнальный слой — «сегодня подходящий момент подсказать клиенту
перевод в страну СНГ?». Коридоры RUB→TJS/UZS/KGS/AMD/KZT (+USD для
sanity-check). Данные — дневные курсы ЦБ РФ, нормированы по номиналу,
`rub_per_unit` (меньше = выгоднее для отправителя).

**Текущий этап:** гибридная матрица «индикатор × коридор × метрики» готова и
прогнана на USD + TJS. Ridge-модель (бывший основной подход) в матрице как один
из индикаторов — и проигрывает. Rule-based индикаторы обыгрывают DCA на +4–5%,
но у каждого есть оговорка. Дальше — комбинирование в единый поток триггеров
(ТЗ п.8).

## 2. Что сделано в этом коммите

### 2.1. `src/signal_layer/indicators.py` (новый)

Библиотека правил-индикаторов из ТЗ (п.2–3). Каждый индикатор — функция
`panel -> DataFrame[iso, signal_date, rub_per_unit]`, строго backward-looking
(rolling-окна, без заглядывания вперёд — тот же контракт, что в `features.py`).

| Индикатор | Скорость | Что делает | Параметры (grid) |
|---|---|---|---|
| `value` | fast | курс в нижних `lo_pct` rolling-`window` high-low диапазона | window∈{20,60,120}, lo_pct∈{0.10,0.20,0.30} |
| `momentum` | fast | `streak` дней снижения подряд | streak∈{3,5} |
| `value_reversal` | medium | VALUE + курс пошёл вверх (отскок от дна) | window∈{20,60,120}, lo_pct∈{0.20,0.30} |
| `reversal_from_min` | slow | разворот вверх от rolling-минимума («окно закрывается») | window∈{60,120}, pct∈{0.01,0.02} |
| `model_ridge` | model | обёртка над существующим `walk_forward_predict` + квантильный порог | нет (пустой grid) |

Ключевое в модуле:
- `evaluate_indicator(...)` — прогон одного индикатора на окне, возвращает
  uplift vs DCA/random + lift/hit/freq. **Считает правдивость по двум hit-rules**:
  value/momentum — по `favourable_now` (курс остался не хуже — это и есть
  «купил дёшево»), reversal/model — по `window_closing` (курс вырос — «дно
  закрылось»). `lift_h5` = lift под своим сценарием, `lift_h5_other` — под
  другим, для кросс-сравнения.
- `calibrate(...)` — walk-forward grid search: лучший медианный uplift-vs-DCA
  по 4 expanding фолдам (медиана, не среднее — один фолд не доминирует).
- `waiting_cost(...)` — цена ожидания: на сколько б.п. курс изменился между
  быстрым сигналом и ближайшим *позже* медленным (ТЗ п.5).

### 2.2. `src/signal_layer/run_indicators.py` (новый)

CLI матрицы. Прогоняет все индикаторы (с per-коридор калибровкой) на последнем
году, пишет `reports/indicators/indicators_matrix.csv` и `waiting_cost.csv`,
печатает вердикт: какие индикаторы информативны / на границе / исключить и
почему.

```bash
uv run python -m signal_layer.run_indicators --corridors USD TJS --out reports/indicators
# на всех шести коридорах идёт ~10-15 мин (Ridge walk-forward долгий)
```

### 2.3. Переиспользовано без изменений

- `simulation.simulate_strategies` — месячный бюджет-контракт (50к ₽/календ.мес
  × месяцев = общий бюджет, делится поровну между покупками каждой стратегии).
- `metrics.evaluate` — lift/hit/advantage/frequency/clustering.
- `run_m0._load_panel` / `_signals_from_predictions` — USD-контекст + порог.

## 3. Главные выводы из матрицы (USD + TJS, последний год)

Полные цифры — в `reports/indicators/indicators_matrix.csv`. Выжимка:

| Коридор | Индикатор | vs DCA | vs random | lift h=5 | freq/нед | вердикт |
|---|---|---|---|---|---|---|
| USD | value | +4.96% | +5.08% | 1.08 | 1.2 | marginal |
| USD | momentum | +3.93% | +4.10% | 0.99 | 0.4 | drop |
| USD | value_reversal | +4.20% | +4.36% | 0.87 | 0.7 | drop |
| USD | reversal_from_min | +5.01% | +5.22% | 1.15 | 0.1 | marginal |
| USD | model_ridge | **−0.96%** | −0.86% | 0.91 | 0.6 | drop |
| TJS | value | +5.37% | +5.49% | 0.71 | 1.1 | drop |
| TJS | momentum | +0.90% | +1.08% | 1.19 | 0.8 | marginal |
| TJS | value_reversal | +4.94% | +5.10% | 0.63 | 0.7 | drop |
| TJS | reversal_from_min | +5.10% | +5.22% | **1.35** | 0.3 | marginal |
| TJS | model_ridge | **−2.70%** | −2.49% | 1.41 | 0.3 | drop |

**Цена ожидания** (value → reversal_from_min): USD +0.6 б.п., TJS **−14 б.п.**
(на TJS ждать подтверждения было выгоднее — быстрый сигнал ловил не дно).

### Что это значит

1. **Ridge-модель проигрывает DCA (−1…−2.7%) — диагноз подтверждён.** Таргет
   `advantage = median(future) − rate` ловит *отскок вверх*, а клиенту нужна
   *абсолютная дешевизна*. Модель сигналит поздно, в ожидании разворота, и
   пропускает реальные просадки. Это была гипотеза, теперь она доказана матрицей.

2. **Все rule-based обыгрывают DCA на +4–5% по валюте.** Тайминг на этом рынке
   реально даёт много (оракул по абсолютной цене давал +5–7% — это верхняя
   граница, value-правила берут большую часть).

3. **Но lift h=5 у многих <1.3, а у некоторых <1.0.** Парадокс: клиенту выгодно
   (+5% валюты), а «правдивость» пуша под сомнением. Причина: value-индикаторы
   срабатывают часто и кластерно (`series_share` 0.9 у USD value), а random
   baseline при `favourable_now` тоже неплох. Это не значит, что индикатор
   бесполезен — uplift vs DCA честнее отражает клиентскую ценность, чем lift над
   random-днём. **Обе метрики нужно показывать вместе** (так и сделано в матрице).

4. **`reversal_from_min` — самый многообещающий медленный.** TJS lift 1.35 (цель
   ≥1.3), USD 1.15, vs DCA +5%. Но частота 0.1–0.3/нед — ниже полосы 1–2/нед.
   Это конфликт: надёжный сигнал редок. Решение — комбинировать fast+slow
   (ТЗ п.8), а не брать один.

5. **Калибровка выбрала `window=120` всем.** Долгое окно — коридоры
   низковолатильны (TJS/UZS/KGS почти копии USD/RUB, см. `signal_layer_v2.md`
   п.5.1), короткое окно даёт шум.

### Исправленные баги (важно для понимания цифр)

В первой итерации матрицы были два бага, которые сильно искажали картину:
- **n_signals считался за всю историю (1338), а не за год (60).** Метрики
  правдивости гонялись по полному ряду с 2000 года. Теперь `evaluate_indicator`
  обрезает сигналы окном `[start, end]` и считает `total_days` по окну.
- **`waiting_cost` был 0.0**, потому что искал медленный сигнал `≥` быстрого и
  ловил тот же день. Теперь строго `>` (позже) — интервал ожидания реальный.

## 4. Что делать дальше (приоритеты)

### 4.1. Ближайшее — комбинирование (ТЗ п.8, основной недостающий кусок)

Матрица показала: ни один индикатор alone не закрывает полосу 1–2/нед с
lift≥1.3. Нужен единый поток триггеров:
- fast (`value`/`momentum`) дают частоту, но шумнее;
- slow (`reversal_from_min`) надёжнее, но редок;
- правило: быстрый сигнал ждёт подтверждения медленным в течение h дней; если
  подтверждение пришло — отправляем; если нет — отправляем по быстрому, но с
  пониженным «доверием» (весом). Цена ожидания (−14 б.п. на TJS) подсказывает,
  когда ждать невыгодно.
- прореживание серий: после сигнала cooldown, как в `_signals_from_predictions`.

## 5. Как запустить

```bash
# Матрица индикаторов (2 коридора, ~3-4 мин)
uv run python -m signal_layer.run_indicators --corridors USD TJS --out reports/indicators

# Дашборд Ridge (Plotly HTML, последний год, модель vs DCA vs random)
uv run python -m signal_layer.dashboard --out reports/dashboard.html

# m0 Ridge walk-forward + метрики
uv run python -m signal_layer.run_m0 train --corridors TJS UZS KGS AMD KZT --out reports/m0

# Сигнал на произвольную дату (проверка no-look-ahead)
uv run python -m signal_layer.run_m0 asof --corridor TJS --date 2024-06-01

# Проверки
uv run ruff check src/
uv run pytest -q
```

Используем `uv` (не pip). Переменная окружения `UV_CACHE_DIR="$TMPDIR/uv-cache"`
нужна только в песочнице, в обычном терминале не требуется.

## 7. Контракты, которые нельзя нарушать

- **No look-ahead.** Сигнал на дату T — только по данным ≤ T. Все индикаторы —
  rolling-окна. Проверяется: `run_m0 asof --date T` даёт тот же сигнал, что и в
  прогоне по истории. Тесты `test_features_have_no_lookahead` и др. — 6 шт,
  должны проходить.
- **Одинаковый бюджет.** Все стратегии тратят `monthly_budget × месяцев`,
  поровну между своими покупками. Отличается только тайминг. Иначе сравнение
  нечестное (кто покупает каждый день тривиально выиграет по объёму).
- **Объяснимость.** Внутри сигнального контура — только правила/статистика,
  без генеративных моделей (требование ТЗ). Ridge остаётся, но как один из
  индикаторов-контролёров, не как финальное решение.
